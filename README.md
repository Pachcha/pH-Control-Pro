# pH Control Pro

ระบบควบคุมค่า **pH** ของน้ำอัตโนมัติ ด้วย ESP32 + **Google Firebase Realtime Database**
ดูค่าและสั่งงานได้จากมือถือหรือคอมพิวเตอร์ทุกที่ที่มีอินเทอร์เน็ต

พัฒนาต่อจากโปรเจกต์ *Water Quality Control System v9.0* โดยตัดส่วนที่ไม่ได้ใช้ออกให้เหลือเฉพาะการคุม pH

---

## ทำอะไรได้บ้าง

- 📊 **วัด pH และอุณหภูมิน้ำ** ตลอดเวลา แสดงบนจอ LCD และบนเว็บ
- 🤖 **คุม pH อัตโนมัติ** — ต่ำไปสั่งจ่าย pH Up สูงไปสั่งจ่าย pH Down พร้อมกวนให้เข้ากัน
- 🎯 **Calibrate 3 จุด** (pH 4.00 / 7.00 / 10.01) เก็บค่าให้เองเมื่อนิ่ง พร้อมตรวจความไวหัววัดและ R²
- ☁️ **ส่งข้อมูลขึ้น Firebase** แบบ realtime เก็บกราฟย้อนหลังและบันทึกเหตุการณ์
- 📱 **หน้าเว็บ Dashboard** ปรับค่าตั้ง สั่งปั๊มด้วยมือ สั่ง calibrate สั่งรีบูตได้จากมือถือ
- 🛡️ **ระบบความปลอดภัย** — จำกัดจำนวนครั้งที่จ่ายสารต่อชั่วโมง, หยุดฉุกเฉิน, ตรวจเซนเซอร์เสีย, watchdog

## ขั้นตอนติดตั้ง

### 1. ตั้งค่า Firebase

1. เข้า [Firebase Console](https://console.firebase.google.com) → **Add project** → ตั้งชื่อโปรเจกต์ (เช่น `ph-control-pro`) → กด Continue จนเสร็จ

2. **สร้าง Realtime Database**
   เมนูซ้าย → **Build** → **Realtime Database** → **Create Database**
   - เลือกโซน **`Singapore (asia-southeast1)`** ← เร็วที่สุดสำหรับประเทศไทย
   - เลือก **Start in locked mode** (เดี๋ยวเราจะวาง Rules เองในขั้นที่ 4)

3. **เปิด Anonymous Authentication**
   เมนูซ้าย → **Build** → **Authentication** → **Get started**
   → แท็บ **Sign-in method** → เลือก **Anonymous** → เปิดสวิตช์ **Enable** → **Save**

   > ถ้าข้ามขั้นนี้ ทั้ง ESP32 และหน้าเว็บจะเข้าระบบไม่ได้

4. **วาง Database Rules**
   กลับไปที่ **Realtime Database** → แท็บ **Rules**
   → ลบของเดิมทิ้ง แล้ววางเนื้อหาจากไฟล์ [`firebase/database.rules.json`](firebase/database.rules.json) → กด **Publish**

5. **คัดลอกค่า 2 ตัวนี้ไว้**
   - **API key** → ไอคอนเฟือง ⚙️ ข้างๆ Project Overview → **Project settings** → แท็บ **General** → ช่อง **Web API Key**
   - **Database URL** → หน้า Realtime Database ลิงก์ที่อยู่เหนือตาราง
     หน้าตาแบบ `https://ชื่อโปรเจกต์-default-rtdb.asia-southeast1.firebasedatabase.app`

### 2. ใส่ค่าลงโค้ด (2 จุด)

> โปรเจกต์นี้ตั้งค่าไว้ให้แล้วสำหรับ Firebase project **`water-quality-4540c`** โซน `asia-southeast1`
> ถ้าคุณใช้โปรเจกต์อื่นหรือเลือกโซนอื่น ต้องแก้ทั้ง 2 จุดข้างล่างให้ตรง

**จุดที่ 1 — เฟิร์มแวร์**

```bash
cp firmware/pH_Control_Pro/secrets.h.example firmware/pH_Control_Pro/secrets.h
```

แล้วเปิด `secrets.h` แก้ทั้ง 4 บรรทัด (ชื่อ WiFi, รหัส WiFi, API key, Database URL)

> ⚠️ ไฟล์ `secrets.h` อยู่ใน `.gitignore` แล้ว จะไม่ถูก push ขึ้น GitHub — **อย่าย้ายค่าเหล่านี้ไปไว้ในไฟล์อื่น** โดยเฉพาะรหัส WiFi

**จุดที่ 2 — หน้าเว็บ**

ใส่ค่าไว้ให้แล้วใน `docs/index.html` (บล็อก `firebaseConfig` ต้น `<script>` ท้ายไฟล์)
ถ้าต้องเปลี่ยนโปรเจกต์หรือโซน ให้แก้ 2 บรรทัดนี้

```js
const firebaseConfig = {
  apiKey:      "AIzaSy...ค่าจริงของคุณ",
  databaseURL: "https://ชื่อโปรเจกต์-default-rtdb.asia-southeast1.firebasedatabase.app"
};
```

> `apiKey` ฝั่งเว็บของ Firebase ไม่ใช่ความลับ ใส่ในไฟล์ที่เป็น public ได้ตามปกติ
> แต่ **`databaseURL` ที่เปิดเผยคู่กับ Anonymous auth แปลว่าใครก็สั่งงานระบบได้** — อ่านหัวข้อ [ความปลอดภัย](#ความปลอดภัย--อ่านก่อนเปิดใช้จริง) ก่อนใช้จริง

### 3. ลงไลบรารีใน Arduino IDE

ผ่าน **Library Manager** (Sketch → Include Library → Manage Libraries)

| ไลบรารี | ผู้พัฒนา |
|---|---|
| Firebase Arduino Client Library for ESP8266 and ESP32 | Mobizt |
| OneWire | Paul Stoffregen |
| DallasTemperature | Miles Burton |

### 4. ตั้งค่าบอร์ดก่อนอัปโหลด

เมนู **Tools** ตั้งดังนี้

| หัวข้อ | ค่าที่ต้องเลือก |
|---|---|
| Board | **ESP32 Dev Module** |
| **Partition Scheme** | **Huge APP (3MB No OTA/1MB SPIFFS)** |
| Upload Speed | 921600 |
| Flash Size | 4MB (32Mb) |

> 🔴 **ต้องเปลี่ยน Partition Scheme เป็น Huge APP เท่านั้น**
> ค่า default ให้พื้นที่โปรแกรมแค่ 1.3 MB แต่โค้ดนี้ใช้ไปแล้ว 1.29 MB (99%) จะคอมไพล์ผ่านแบบเฉียดฉิว
> พอเปลี่ยนเป็น Huge APP จะเหลือใช้แค่ 41% ของ 3 MB มีที่ว่างให้แก้โค้ดเพิ่มได้สบาย

ถ้าใช้ `arduino-cli`:

```bash
arduino-cli compile --fqbn "esp32:esp32:esp32:PartitionScheme=huge_app" firmware/pH_Control_Pro
```

## Calibrate เซนเซอร์ pH

**ต้องทำก่อนใช้งานจริงเสมอ** — ยังไม่ calibrate ระบบจะไม่อ่านค่า pH และไม่จ่ายสารใดๆ

1. เตรียมน้ำยา buffer **pH 4.00**, **7.00**, **10.01** และน้ำสะอาดสำหรับล้างหัววัด
2. เริ่มได้ 2 ทาง
   - **กดปุ่ม BOOT บนบอร์ดค้าง 3 วินาที**
   - หรือกดปุ่ม **🎯 Calibrate** บนหน้าเว็บ
3. ทำทีละขั้น (3 ขั้น) ดูความคืบหน้าได้ทั้งจอ LCD และหน้าเว็บ
   - จุ่มหัววัดในน้ำยาตามที่จอบอก คนเบาๆ แล้วปล่อยนิ่ง
   - **ระบบเก็บค่าให้เองเมื่อพร้อม** — ต้องผ่านทั้ง 2 เงื่อนไข:
     อยู่ในขั้นนั้นครบ **30 วินาที** และแรงดัน**นิ่งต่อเนื่อง 10 วินาที**
     (เงื่อนไขแรกเผื่อเวลาล้างหัววัด กันเก็บค่าตอนหัววัดยังแช่น้ำล้างอยู่)
   - อยากเก็บทันทีไม่ต้องรอ กดปุ่ม **BOOT** หรือปุ่มบนหน้าเว็บได้
   - **ล้างหัววัดด้วยน้ำสะอาดแล้วซับให้แห้งก่อนเปลี่ยนน้ำยาทุกครั้ง**
   - ถ้าค่าไม่นิ่งพอภายใน 5 นาที ระบบจะยกเลิกแทนการเก็บค่าที่เชื่อไม่ได้
4. เสร็จแล้วระบบตรวจ **3 ด่าน** ต้องผ่านครบถึงจะใช้งานได้
   | ด่าน | เกณฑ์ | ไม่ผ่านแปลว่า |
   |---|---|---|
   | ความไวหัววัด | ช่วงแรงดัน ≥ **200 mV** | หัววัดแทบไม่ตอบสนอง — ตรวจ BNC / สภาพหัววัด / ไฟเลี้ยงโมดูล |
   | ทิศทาง | แรงดันไล่ไปทางเดียวกันทั้ง 3 จุด | เก็บค่าตอนยังไม่นิ่ง หรือไม่ได้ล้างหัววัด |
   | ความเป็นเส้นตรง | **R² > 90%** | จุดใดจุดหนึ่งเพี้ยน |

   > ⚠️ **R² สูงอย่างเดียวไม่พอ** — R² วัดแค่ว่า 3 จุดเรียงเป็นเส้นตรงไหม
   > ไม่ได้วัดว่าหัววัดไวพอไหม หัววัดที่เสียจะให้แรงดันเดินสุ่มทีละนิด
   > ถ้าบังเอิญไต่ขึ้นตามลำดับ R² จะสูงถึง 99% ทั้งที่เป็นแค่ noise
   > ระบบจึงตรวจความไวเป็นด่านแรกเสมอ ดูค่าได้จากแถว "ความไวหัววัด" บนหน้าเว็บ
   > (ปกติ ≥ 59 mV/pH ตามทฤษฎี Nernst)

ค่าที่ได้ถูกบันทึกลง EEPROM ถอดไฟแล้วยังอยู่ ไม่ต้องทำใหม่ทุกครั้ง

> **หลังแฟลชเฟิร์มแวร์นี้ครั้งแรกต้อง calibrate ใหม่** เพราะโครงสร้างข้อมูลใน EEPROM เปลี่ยนไปจากเวอร์ชันเดิม ระบบจะตรวจเจอแล้วโหลดค่า default ให้อัตโนมัติ

## ความปลอดภัย — อ่านก่อนเปิดใช้จริง

### 1. ใครก็ตามที่รู้ Database URL สั่งงานระบบได้

โปรเจกต์นี้ใช้ **Anonymous Authentication** ซึ่งแปลว่าใครก็สมัครบัญชีนิรนามเข้ามาได้
Rules ที่ให้ไว้จำกัดได้แค่ *รูปแบบและช่วงของค่า* (เช่น ตั้ง targetPH เกิน 11 ไม่ได้) แต่ **ไม่ได้จำกัดว่าใครเข้าได้บ้าง**

ตัวที่จำกัดความเสียหายไว้อยู่คือ **ลิมิต 6 ครั้งต่อชั่วโมง ซึ่งมีผลกับคำสั่งมือจากหน้าเว็บด้วย**
(`startDosing()` เรียก `canDoseNow()` ทั้งทางอัตโนมัติและทางสั่งมือ) คนนอกจึงสั่งปั๊มทำงานได้
มากสุดราว 18 วินาทีต่อชั่วโมง ไม่ใช่เทได้ไม่จำกัด — แต่ก็ยังปิด/เปิดโหมดอัตโนมัติและสั่งรีบูตได้อยู่ดี

สำหรับระบบที่ควบคุมการจ่ายสารเคมีจริง แนะนำอัปเกรดเป็น **Email/Password** แทน

- Firebase Console → Authentication → เปิด **Email/Password** แล้วสร้างบัญชีไว้ 1 บัญชี
- ในเฟิร์มแวร์ ใส่ `fbAuth.user.email` / `fbAuth.user.password` แทนการเรียก `Firebase.signUp()`
- ในหน้าเว็บ เปลี่ยน `signInAnonymously()` เป็น `signInWithEmailAndPassword()`
- แก้ Rules เป็น `".read": "auth.uid === 'UID-ของบัญชีนั้น'"`

### 2. API key ของ Firebase ไม่ใช่ความลับ

`apiKey` ฝั่งเว็บถูกออกแบบมาให้เปิดเผยได้ ใส่ไว้ใน `docs/index.html` ที่เป็น public ได้ตามปกติ
**ความปลอดภัยทั้งหมดอยู่ที่ Database Rules** — ห้ามตั้ง Rules เป็น `".read": true, ".write": true` เด็ดขาด

### 3. รหัส WiFi ต้องไม่ขึ้น GitHub

อยู่ใน `secrets.h` ซึ่ง `.gitignore` กันไว้แล้ว ก่อน commit ทุกครั้งควรเช็คด้วย

```bash
git status --porcelain | grep secrets.h
```

ถ้าไม่มีผลลัพธ์ออกมา = ปลอดภัย

## แก้ปัญหาที่พบบ่อย

| อาการ | สาเหตุและวิธีแก้ |
|---|---|
| `Sign-Up FAILED: ... CONFIGURATION_NOT_FOUND` | ยังไม่ได้เปิด **Anonymous** ใน Authentication |
| `Sign-Up FAILED` แต่ WiFi ต่อติด | เวลาไม่ตรง — ดูว่าบรรทัด `[NTP] sync สำเร็จ` ขึ้นไหม ถ้าไม่ขึ้นแปลว่าเราเตอร์บล็อกพอร์ต NTP (123/UDP) |
| คอมไพล์ผ่านแต่บอร์ดรีบูตวนไม่หยุด | ยังไม่ได้เปลี่ยน **Partition Scheme เป็น Huge APP** หรือไฟไม่พอ ให้แยกไฟเลี้ยงปั๊มออกจาก ESP32 |
| หน้าเว็บขึ้น "ยังไม่ได้ตั้งค่า Firebase" | ยังไม่ได้แก้ `firebaseConfig` ใน `docs/index.html` |
| หน้าเว็บขึ้น "เข้าสู่ระบบไม่ได้" | ยังไม่ได้เปิด Anonymous auth หรือใส่ apiKey ผิด |
| หน้าเว็บเชื่อมต่อได้แต่ไม่มีข้อมูล | ยังไม่ได้ Publish Rules หรือบอร์ดยังส่งข้อมูลไม่สำเร็จ ให้ดู Serial Monitor |
| **ไม่ผ่านด่าน "span ... noisy"** | หัววัดแทบไม่ตอบสนอง เรียงตามความน่าจะเป็น: ①ข้อต่อ BNC หลวม ขันใหม่ให้แน่น ②หัววัดเคยปล่อยแห้ง (ต้องเก็บแช่ KCl เสมอ) ลองแช่ buffer pH 4 ข้ามคืน ③โมดูล PH4502C ต้องใช้ไฟ **5V** ถ้าจ่าย 3.3V ออปแอมป์แกว่งไม่ออก เอาต์พุตจะยุบเหลือช่วงแคบ — จ่าย 5V แล้วต่อวงจรแบ่งแรงดัน 10k/20k ก่อนเข้า GPIO 36 |
| **ไม่ผ่านด่าน "not monotonic"** | เก็บค่าตอนหัววัดยังไม่นิ่ง หรือไม่ได้ล้างหัววัดระหว่างเปลี่ยนน้ำยา ทำให้น้ำยาปนกัน |
| **R² ต่ำกว่า 90%** | หัววัดสกปรก/เสื่อม, น้ำยา buffer หมดอายุ, หรือสายสัญญาณโดนรบกวน (เดินสายห่างจากไฟ AC และสายปั๊ม) |
| **ค่า pH กระโดดไปมาหลาย pH** | slope ชันเกินไปเพราะช่วงแรงดันแคบ — ดูแถว "ความไวหัววัด" ถ้าต่ำกว่า 40 mV/pH ต้องแก้ที่หัววัดก่อน กรองสัญญาณเพิ่มไม่ช่วย |
| ค่า pH แกว่งไปมาไม่นิ่ง | สายเซนเซอร์เดินใกล้สายไฟ AC เกินไป หรือกราวด์ไม่ได้ต่อร่วมกัน |
| ระบบจ่ายสารแล้ว pH แกว่งเกินเป้า | ลด **เวลาจ่ายต่อครั้ง** ลง แล้วเพิ่ม **เวลาพัก** ขึ้น จากหน้าเว็บ |
| ขึ้น "จ่ายสารครบลิมิตต่อชั่วโมง" | ระบบป้องกันทำงานถูกต้องแล้ว — ไปตรวจว่าเซนเซอร์อ่านค่าถูกไหม ปั๊มดูดสารได้จริงไหม แล้วค่อยเปิดโหมดอัตโนมัติใหม่ |
